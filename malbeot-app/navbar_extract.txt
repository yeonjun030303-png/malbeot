## ① 지금 진행 중인 것 — 키보드 간격 버그 + 하단 네비 버그, 사용자 스크린샷 대기 중

### 배경
아래 두 버그를 여러 차례 코드 추측만으로 패치했으나 실기기에서 재확인 결과 **둘 다 여전히 미해결**:

1. **채팅창에서 키보드를 띄우면, 입력창과 키보드 사이에 빈 간격(층)이 생김** — 카톡처럼 입력창이 키보드 바로 위에 붙어야 하는데 안 붙음
2. **앱을 완전히 종료했다가 재시작하면, 하단 네비게이션 바(홈/커뮤니티/채팅/마이페이지)가 테두리만 보이고 버튼이 안 보이며 클릭도 안 됨** — 단, 다른 사람 프로필 화면을 한 번 열었다가 닫으면 그 순간 정상화됨

추측 기반 패치(0-70~0-72, 커밋 e69e989/28ae248/6d5b5bb)를 반복 적용했지만 실측 없이 진행해서 계속 실패함. → **더 이상 추측하지 않고, 실제 기기 수치를 눈으로 확인하는 방식으로 전환함.**

### 0-73에서 한 일 (완료, 커밋 push까지 완료됨)
- `public/index.html`에 **임시 디버그 오버레이** 추가함: 화면 좌상단에 초록색 작은 글씨 박스가 뜨고, 아래 값들을 300ms마다 실시간 갱신해서 보여줌
  - `innerH`(전체 화면 높이) / `vpH`(visualViewport 높이) / `gap`(둘의 차이 = 키보드가 실제로 감지되는지 확인용)
  - `body.keyboard-open` 클래스가 켜져 있는지 여부
  - `#appContainer`와 `#chatModal`의 style.height 값 + 실제 렌더링된 rect 높이
  - `.chat-input-bar`(입력창)의 화면상 bottom 좌표
  - `.bottom-nav`(하단 네비)의 rect(top/height/bottom), display/visibility/opacity/pointerEvents/zIndex 계산값, className
- 이 오버레이 자체는 배포 후 정상적으로 화면에 뜨는 것까지 사용자가 확인함(좌상단에 초록 박스 보임)
- **아직 못 받은 것**: 문제가 실제로 재현된 순간의 그 박스 안 수치. 사용자에게 아래 2장의 스크린샷을 요청한 상태이고, 다음 세션 시작하면 이 응답을 기다리는 중인지부터 확인할 것

### 다음 세션에서 할 일
1. 사용자가 아래 스크린샷을 줬는지 먼저 확인:
   - **① 채팅창에서 키보드를 띄운 상태** 화면 전체 캡쳐(디버그 박스 + 입력창 + 키보드까지 다 보이게)
   - **② 앱을 완전히 종료(백그라운드에서도 스와이프로 제거)했다가 재시작해서, 하단 네비가 안 보이는 상태가 재현된 순간** 화면 전체 캡쳐(디버그 박스 포함)
2. 아직 안 왔으면 이어서 요청할 것
3. 받으면: 박스 안 수치를 보고 **추측 없이 정확한 원인**을 특정해서 패치
   - 키보드 버그 후보: `gap` 값이 실제로 커지는지(visualViewport가 키보드를 감지하긴 하는지) 확인 필요 — `capacitor.config.json`이 `ios: {contentInset: "automatic"}`로 되어 있어서, 이 설정 때문에 iOS가 키보드를 네이티브 방식으로 처리해 `visualViewport.height`가 아예 안 바뀔 가능성이 있음(그렇다면 기존 접근 자체가 원천적으로 작동 불가능했던 것)
   - 하단 네비 버그 후보: nav의 rect가 0이거나 화면 밖에 있는지, display/visibility가 실제로 숨겨진 상태인지, 아니면 값은 멀쩡한데 다른 요소에 z-index로 가려진 건지 — 지금은 순수 추측이고 스크린샷 봐야 확정 가능
4. **원인 확정하고 진짜 패치 적용한 뒤에는, 디버그 오버레이 코드(0-73에서 추가한 부분)를 반드시 제거할 것** — `updateDebugOverlay`, `dbg` 관련 코드 전체, `<!-- 임시 디버그 오버레이 -->` 주석으로 감싸진 블록 통째로 삭제. 이건 진단용 임시 코드라 실제 서비스에 계속 남아있으면 안 됨(Apple 재심사 때도 불필요한 코드로 지적받을 수 있음)

## ⑥ 기타 참고사항

- 패치 전달 방식은 기존과 동일: `code 파일명.py`로 새 파일 만들어서 파이썬 코드 통째로 전달 → 사용자가 복붙 후 `python 파일명.py` 실행 → `[완료]` 확인 → `git add`/`commit`/`pull --rebase`/`push`. 클로드는 이 저장소에 push 권한 없음.
- index.html은 `node -c`로 직접 문법 검증 불가(HTML 파일이라서) — 필요시 인라인 `<script>` 블록만 추출해서 Node Function 생성자로 검증하는 우회 방식 사용해왔음.
- 여러 명령 이어붙일 때는 `&&` 대신 `;` 사용(PowerShell). 코드블록은 쪼개지 말고 한 번에 통째로 복붙 가능하게 요청받음.
